# Shipped native architecture

Estragon is a Godot addon. Godot owns Node lifetime, SceneTree, transforms, rendering and platform events. Estragon owns bounded measurement/arrangement, native UI semantics and Gogo compilation. [ADR-0015](DECISIONS.md#adr-0015--ggx-node-native-composition-and-layout-first-estragon) is the accepted direction; C4 #83 retires the old parallel UI and stage-0 JSON paths.

The compiler lexes GDScript and GGX islands into typed source-spanned syntax. A static resolver reads native/explicit-import metadata without instantiating authored Nodes. Validation enforces Node-only children, native typed props and named signal Callables; deterministic emission produces typed GDScript and range maps. Compiler analysis/codegen has no editor, drawing or live SceneTree dependency. Godot supplies final semantic/type validation. Editor build_service stages all outputs, validates actual resource paths and refreshes Script identity transactionally, rolling back on errors.

Visual 2D widgets derive from Node2D; 3D participants derive from Node3D. Both compose runtime/node/internal/layout_core.gd. Native coordinators subscribe to child/property/viewport events, cache measurements and batch affected-branch reflow. Native bounds adapters preserve native/layout axis authority and feedback guards. Plain Nodes interrupt layout; explicit entries re-enter it. No generic Node measurement, universal 3D wrapping, polling, virtual DOM or full-tree rebuilding.

Canonical widgets and the retained Counter use native Font/draw APIs and an entry-scoped weak pointer router. Node.add_child is the only attachment API; owner assignment/persistence is separate. Removal/reparent/free and signal cleanup follow Godot, verified with packing/reload and retained identities. No RefCounted component wrapper tree or RenderingServer surface remains; RefCounted mathematical/compiler helper objects are composition internals, not UI elements.

Normal authoring/Play needs only the addon and Godot. See [language](GOGO_LANGUAGE.md), [UI](NODE_UI.md), [runtime](NODE_RUNTIME.md), [editor](EDITOR.md) and [test/distribution gates](TESTING.md). Historical C01/B1–C3 reports preserve their actual failures and supported scope; they do not define active release requirements. Addon acceptance requires current native compiler/editor/runtime/graphics/distribution evidence on the two approved Linux engines; no standalone executable export gate.
