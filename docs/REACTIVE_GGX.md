All GGX now produces virtual Element descriptions. A typed `build_view() -> Element` observes actual Gogo getter reads, including locals, model replacement, conditional paths and GGX-containing helpers. Ordinary helper bodies are opaque and memoized by explicit arguments. One external manager coalesces signals, processes parents before nested components, preflights desired output, and changes only declared props/handlers/native structure that differ. It retains native Nodes and native animation/state for unchanged declarations. There are no explicit-self dependency restrictions, generated reader/source methods, property-binding helper children, separate queues or duplicate subscriptions.

Run `examples/reactive/Demo.tscn` for nested Gogo model text/style/width/gap updates; the canonical Counter uses the same path. A computation subscribes once per read object/property signal even when several props use it. Model replacement rewires after safe deferred recomposition; stale reads disconnect, host exit suspends and reentry reconnects, disposal cancels queued work. Independent nested components retain separate scopes. Repeated helpers must be pure; lifecycle/events perform once-only effects. Null models use explicit native conditional alternatives; the demo omits text/style/width props while null, preserving native defaults/last values through ordinary reconciliation rather than a hidden path evaluator.

Native widget setters distinguish paint-only updates and affected-branch layout. Actual Node2D/Node3D/layout/native transforms remain authoritative; #88's expanded transform policy is outside F04. Managed output is transient, authored/foreign scene ownership is separate, and packing/reload reconstructs source-authoritative output once.

`@bindable` signals retain their typed equality/initialization/reentrancy/inheritance semantics. Raw Array/Dictionary in-place writes and ordinary native properties do not magically notify; bindable reference reassignment is supported. [Conditional composition](F02_CONDITIONALS.md), [mapped/keyed arrays](F03_LISTS.md), [bindable model contract](BINDABLE_PROPERTIES.md).

## Function caching and remaining target boundary

- **Functions containing authored GGX are reactive render functions:** their own bindable getter reads (including locals/branches) invalidate memoized GGX **structure**. A zero-argument `make_badge()` with `<Text text={self.name} />` or a conditional child reruns on `name_changed`; no separate per-property live-expression engine is needed.
- **Ordinary functions without GGX** are memoized by explicit arguments only at render call sites, including imported `.gd` functions and manually created Elements. A zero-argument ordinary helper is static; internal hidden getter reads do not establish subscriptions. Pass changing inputs explicitly. Handler references are not render-time calls.
- Two calls to `make_badge()` mount distinct native Nodes and own independent cache/observation lifetimes. Keyed list instances use keyed identity, unkeyed use position. An Element description reused at multiple mount slots does not alias native Nodes or mutable subscriptions. The existing manager handles changed conditions and source replacement, with cleanup on branch removal/unmount.
- Signal changes in observable model arguments invalidate dependent caches without changed object identity or revision counters. Ordinary native Array/Dictionary in-place changes remain unobserved. ArrayCollection/upward propagation is CORE-02, not implemented here.
- Future control work makes GGX direct writable paths implicitly **two-way** with compatible bindable destination properties; local snapshot/computed expressions stay one-way. Native model writes remain synchronous; reconciliation remains deferred/coalesced. See [ADR-0031](DECISIONS.md#adr-0031--ggx-implied-reactive-render-functions-automatic-memoizationbinding-and-observable-typed-data), [#195](https://github.com/papercraftgames/Estragon/issues/195) and [#200](https://github.com/papercraftgames/Estragon/issues/200).
